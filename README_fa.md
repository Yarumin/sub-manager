<h1 align="center">Sub Manager</h1>

<p align="center">پنلی برای مدیریت سابسکریپشن‌ها و کانفیگ‌های پروکسی روی Cloudflare Workers</p>

<br>

## معرفی

Sub Manager یک پنل شخصی برای تجمیع سابسکریپشن‌های پروکسی و کانفیگ‌های دستی (VLESS، Trojan، Shadowsocks، VMess) در یک لینک خروجی واحد است، همراه با پردازش‌های قابل تنظیم روی هر کانفیگ — از جمله جایگزینی آی‌پی تمیز، فیلتر پورت، رفع محدودیت آپلود و موارد دیگر. کل پروژه به‌صورت یک Cloudflare Worker به همراه یک KV namespace اجرا می‌شود، بدون سرور یا دیتابیس خارجی، و بدون هزینه‌ی اضافه بر پلن رایگان کلودفلر برای استفاده‌ی شخصی معمول.

## ویژگی‌ها

- **تجمیع چند منبع** — ترکیب لینک‌های سابسکریپشن و کانفیگ‌های دستی در یک خروجی واحد.
- **جایگزینی آی‌پی تمیز** — جایگزینی آدرس هر کانفیگ با یک آی‌پی از یک لیست مدیریت‌شده، در حالت `multiply` (یک کانفیگ خروجی به‌ازای هر آی‌پی) یا `random` (یک آی‌پی تصادفی برای هر کانفیگ).
- **تنظیمات مستقل هر بخش** — هر منبع، یا هر لینک داخل یک منبع، تنظیمات جداگانه‌ی خودش را دارد: لیست آی‌پی تمیز، فیلتر پورت، یک کانفیگ برای هر پورت، و محدود کردن جایگزینی فقط به رنج‌های شناخته‌شده‌ی کلودفلر.
- **به‌روزرسانی خودکار منابع** — هر منبع لینکی با بازه‌ی زمانی خودش به‌روز می‌شود؛ این به‌روزرسانی به‌صورت lazy در اولین درخواست بعد از موعد مقرر انجام می‌شود. نیازی به Cron Trigger نیست، هرچند می‌توان برای به‌روزرسانی پیش‌دستانه در پس‌زمینه یکی اضافه کرد.
- **پشتیبان‌گیری و بازیابی** — خروجی‌گیری از منابع، لیست‌های آی‌پی تمیز و اتصالات کلودفلر در یک فایل JSON، و بازیابی بعدی در حالت ترکیب یا جایگزینی.
- **آمار مصرف کلودفلر** — اتصال اختیاری یک توکن API کلودفلر برای نمایش تعداد درخواست‌های روزانه‌ی Worker در پنل.
- **رفع محدودیت آپلود** — تنظیم `fingerprint` و `cipherSuites` در لایه‌ی TLS برای کانفیگ‌های VLESS/Trojan، بر اساس روشی که [Patterniha](https://github.com/patterniha) در [این پول‌ریکوئست به v2rayNG](https://github.com/2dust/v2rayNG/pull/5900) ارائه کرده است.
- **کنترل روی تک‌تک کانفیگ‌ها** — تغییر نام، جابه‌جایی ترتیب، و غیرفعال‌سازی موقت هر کانفیگ در یک بخش بدون حذف آن.

## محدودیت‌ها

- این پنل خودش پیاده‌سازی پروکسی نیست — Worker ترافیک VLESS/Trojan/Shadowsocks را مستقیماً پردازش نمی‌کند. فقط کانفیگ‌هایی را که از قبل به یک مقصد فعال اشاره می‌کنند ذخیره، ادغام و بازنشر می‌کند.
- پلن رایگان کلودفلر روزانه ۱۰۰ هزار خواندن و ۱۰۰۰ نوشتن روی KV می‌دهد که بین کل عملکرد Worker مشترک است. برای استفاده‌ی شخصی کافی است؛ در صورت سرو کردن تعداد زیاد درخواست سابسکریپشن باید در نظر گرفته شود.
- هر بخش (یک لینک، یا گروه کانفیگ‌های دستی) حداکثر ۱۰۰۰ کانفیگ پایه نگه می‌دارد. خروجی نهایی هر بخش بعد از ضرب در تعداد آی‌پی‌های تمیز حداکثر ۶۰۰۰ خط است؛ مازاد بر آن به‌صورت تصادفی نمونه‌برداری می‌شود، نه اینکه همه شامل شوند.
- واکشی یک لینک سابسکریپشن بعد از ۱۵ ثانیه timeout می‌شود؛ منابع کند یا غیرقابل‌دسترس به‌عنوان ناموفق علامت می‌خورند، نه اینکه کل درخواست را معطل نگه دارند.

## راه‌اندازی

فقط به یک اکانت رایگان کلودفلر نیاز است.

1. **ساخت KV namespace.** داشبورد کلودفلر → **Workers & Pages** → **KV** → **Create namespace**. نام دلخواه است، مثلاً `sub-manager-db`.
2. **ساخت Worker.** **Workers & Pages** → **Create** → **Workers**، وارد کردن یک نام، سپس **Deploy**. کد پیش‌فرض در مرحله‌ی ۴ جایگزین می‌شود.
3. **اتصال KV namespace.** ورود به Worker → **Settings** → **Bindings** → **Add binding** → **KV namespace**. مقدار **Variable name** باید دقیقاً `SUB_DB` باشد، namespace ساخته‌شده در مرحله‌ی ۱ انتخاب شود، سپس **Save**.
4. **قرار دادن کد.** دانلود `worker.js` از بخش [Releases](https://github.com/Yarumin/sub-manager/releases). ورود به بخش **Edit code** در Worker، جایگزینی محتوای موجود با فایل دانلودشده، سپس **Deploy**.
5. **تنظیم رمز عبور ادمین.** Worker → **Settings** → **Variables and Secrets** → **Add**. نوع: **Secret**، نام: `ADMIN_PASSWORD`، مقدار: یک رمز دلخواه. **Save and deploy**.

   > در صورت عدم تنظیم `ADMIN_PASSWORD`، پنل با رمز پیش‌فرض `admin123` کار می‌کند و تا تنظیم یک Secret واقعی، یک هشدار نمایش می‌دهد. رمز پیش‌فرض فقط برای بررسی اولیه در نظر گرفته شده است.

6. آدرس `https://<worker-name>.<subdomain>.workers.dev/app` باید باز و برای شروع کار با پنل وارد شود.

تنظیم دیگری لازم نیست.

### به‌روزرسانی به نسخه‌ی جدید

تکرار مراحل ۴ و در صورت نیاز ۵ کافی است — جایگزینی کد Worker تأثیری روی داده‌های موجود در KV namespace (منابع، لیست‌های آی‌پی تمیز، اتصالات کلودفلر) ندارد.

### اختیاری: Cron Trigger

منابع همین حالا هم در اولین درخواست بعد از موعد مقرر، خودشان به‌روز می‌شوند. Cron Trigger علاوه بر این، این به‌روزرسانی را به‌صورت پیش‌دستانه در پس‌زمینه هم انجام می‌دهد: Worker → **Settings** → **Triggers** → **Cron Triggers** → **Add Cron Trigger**، مثلاً `0 * * * *` برای هر ساعت.

## اجرا از روی سورس

ساخت محلی فایل Worker، یا دیپلوی مستقیم از روی سورس ماژولار با [Wrangler](https://developers.cloudflare.com/workers/wrangler/) — که برای اکثر کاربران لازم نیست، چون فایل آماده‌ی `worker.js` در بخش [Releases](https://github.com/Yarumin/sub-manager/releases) موجود است — به [Node.js](https://nodejs.org) نیاز دارد.

```bash
git clone https://github.com/Yarumin/sub-manager.git
cd sub-manager
npm install
```

**گزینه‌ی الف — ساخت یک فایل `worker.js` تکی و قرار دادن دستی آن** (خروجی‌ای یکسان با فایل ریلیز):

```bash
npm run build
```

خروجی در `dist/worker.js` نوشته می‌شود و محتوای آن باید مطابق مرحله‌ی ۴ بخش راه‌اندازی، در ویرایشگر Worker جایگزین شود.

**گزینه‌ی ب — دیپلوی مستقیم از روی سورس با Wrangler** (بدون کپی/پیست دستی):

```bash
npx wrangler login
```

مقدار `REPLACE_WITH_YOUR_KV_NAMESPACE_ID` در فایل `wrangler.jsonc` باید با آیدی KV namespace (داشبورد کلودفلر → Workers & Pages → KV → مشاهده‌ی namespace) جایگزین شود، سپس:

```bash
npx wrangler deploy
npx wrangler secret put ADMIN_PASSWORD
```

هر دو گزینه رفتار یکسانی از Worker تولید می‌کنند.

## ساختار پروژه

```
src/
  index.js          نقطه‌ی ورود (fetch / scheduled)
  constants.js
  utils/             توابع کمکی بدون وضعیت
  authz/             سشن، بررسی رمز عبور، محدودسازی نرخ ورود
  configEngine/      پارس کانفیگ، اثرانگشت‌گیری، تولید خروجی
  storage/           خواندن/نوشتن KV، خروجی/ورودی بک‌آپ
  sync/              واکشی سابسکریپشن و به‌روزرسانی خودکار
  api/               هندلرهای مسیر /api/*
  publicApi/         مسیر عمومی /sub/{slug}
  panel/             HTML پنل ادمین + اسکریپت سمت کلاینت
scripts/
  build.mjs          باندل کردن src/ به dist/worker.js
wrangler.jsonc       تنظیمات `wrangler dev` / `wrangler deploy`
```
